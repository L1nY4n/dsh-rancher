# Pod list pagination: Kubernetes and Rancher Steve

The current client lists Pods through Rancher's Kubernetes proxy at `/k8s/clusters/{cluster}/api/v1/pods` ([client code](../src/client.js)). Steve's `/v1/{type}` is a separate API: Steve documents `/api/*` as directly proxied to Kubernetes, while `/v1` adds its own list processing ([Steve API usage](https://github.com/rancher/steve/blob/main/README.md#api-usage)). The two pagination contracts should not be mixed.

## Kubernetes Pod LIST

- `GET /api/v1/pods?limit=N` returns up to `N` items and, if more exist, an opaque `metadata.continue`. Send that token with the **same list query** (apart from `continue`) until it is empty. A page may contain fewer than `N` items, even zero; only `continue` determines whether another page exists ([API chunking](https://kubernetes.io/docs/reference/using-api/api-concepts/#retrieving-large-results-sets-in-chunks), [ListOptions contract](https://github.com/kubernetes/apimachinery/blob/master/pkg/apis/meta/v1/types.go#L414-L445)).
- Continued chunks share the initial list's `resourceVersion` and represent one consistent snapshot. Tokens normally expire after about five minutes; on `410 Gone`, restart from the first request to keep that guarantee. The replacement token supplied with a `410` can resume from a *new* snapshot, so it must not be spliced into an exact snapshot traversal ([API chunking](https://kubernetes.io/docs/reference/using-api/api-concepts/#retrieving-large-results-sets-in-chunks), [ListOptions contract](https://github.com/kubernetes/apimachinery/blob/master/pkg/apis/meta/v1/types.go#L423-L445)).
- `fieldSelector` supports equality/inequality on `metadata.name`, `metadata.namespace`, and documented Pod fields such as `spec.nodeName`, `status.phase`, and `status.podIP`; unsupported fields error. It has no substring or set-membership operator, so an arbitrary name/IP search or a multi-namespace OR cannot be expressed as a Pod field selector. `labelSelector` can select labels, including a set of values for one label, but is a different filter ([field selectors](https://kubernetes.io/docs/concepts/overview/working-with-objects/field-selectors/), [label selectors](https://kubernetes.io/docs/concepts/overview/working-with-objects/labels/#list-and-watch-filtering)). Pod `status.phase` is only a high-level lifecycle summary, not Ready state or the UI's computed health ([Pod phase](https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/#pod-phase)).
- Kubernetes LIST options provide no arbitrary server-side `sort`, substring `search`, or exact `count` parameter ([ListOptions](https://github.com/kubernetes/apimachinery/blob/master/pkg/apis/meta/v1/types.go#L366-L445)). `metadata.remainingItemCount` is optional and only an estimate; it is omitted when field/label selectors are used and on a complete list. An exact total for the snapshot requires consuming every chunk ([API chunking](https://kubernetes.io/docs/reference/using-api/api-concepts/#retrieving-large-results-sets-in-chunks), [ListMeta](https://github.com/kubernetes/apimachinery/blob/master/pkg/apis/meta/v1/types.go#L84-L94)).

## Rancher Steve `/v1` alternative

Steve documents `limit`/`continue` over its SQLite-backed list cache (default limit: 100,000). Its `filter` supports substring matching and OR across designated fields; `sort` supports indexed fields; `pagesize`/one-indexed `page` provides numbered pages; list responses include `count` and `pages`. Supported filter/sort fields are limited to common and type-specific indexed attributes, not arbitrary Pod JSON ([Steve list query parameters](https://github.com/rancher/steve/blob/main/README.md#list-specific-query-parameters), [Pod indexed fields](https://github.com/rancher/steve/blob/main/pkg/stores/sqlproxy/proxy_store.go#L98-L124)). Steve says numbered pages return the **latest** version; `revision` imposes a minimum cache resource version, not a fixed snapshot. Its documentation does not promise Kubernetes-style snapshot consistency across Steve pages or `continue` chunks ([Steve `page`, `pagesize`, `revision`](https://github.com/rancher/steve/blob/main/README.md#page-pagesize-and-revision)). These features apply only if the Pod list is moved to a Steve `/v1` route.

## UI cursor implications

1. For the current Kubernetes route, keep the first request and each returned cursor keyed by cluster, namespace scope, selectors, and page size. Fetch forward with the cursor; use cached pages/cursors for Back. There is no offset or arbitrary page jump. Reset the chain when query scope changes or a cursor expires. Treat a short or empty page with a nonempty `continue` as incomplete ([ListOptions contract](https://github.com/kubernetes/apimachinery/blob/master/pkg/apis/meta/v1/types.go#L414-L445)).
2. Distinguish **loaded items** from **total items** until traversal finishes. Global sort, free-text search, grouping totals, health counts, and restart totals cannot be computed accurately from only the visible Kubernetes chunk. Sorting or filtering each chunk locally yields only page-local results. Push supported exact filters such as node name into the LIST query; for multiple selected namespaces, use separate namespace lists/cursors or explicitly load/filter an all-namespace list ([field selectors](https://kubernetes.io/docs/concepts/overview/working-with-objects/field-selectors/), [API chunking](https://kubernetes.io/docs/reference/using-api/api-concepts/#retrieving-large-results-sets-in-chunks)).
3. If server-side indexed search/sort and numbered pages are required, evaluate Steve `/v1` against the deployed Rancher version and the specific indexed fields. Its reported `count`/`pages` describe each cache-backed response; do not present them as a fixed total across changing numbered pages ([Steve list query parameters](https://github.com/rancher/steve/blob/main/README.md#list-specific-query-parameters), [Steve page semantics](https://github.com/rancher/steve/blob/main/README.md#page-pagesize-and-revision)).
